# Grilling — интервью по фронтиру

Решения образуют **дерево**: каждый ответ открывает следующие вопросы. Работай **раундами
по фронтиру** — задавай только вопросы, все предпосылки которых уже решены. Вопрос,
зависящий от другого открытого вопроса, принадлежит следующему раунду, не этому.

## Правила

1. **Факты — твоя работа, решения — владельца.** Всё, что можно посмотреть (файлы, граф,
   git, реестры), смотри сам ДО вопроса. Вопрос, отвечаемый чтением файла, — брак.
2. **Каждый вопрос — с рекомендацией.** Номер, суть, варианты, твой рекомендуемый ответ
   и почему. Владелец чаще подтверждает/правит, чем выбирает с нуля.
3. **Один раунд — одно сообщение (decision-пакет):** весь текущий фронтир разом,
   нумерованный (`D1, D2, …`), без вопросов вне фронтира. Если ведёшь доску — статус
   решений `asked(<дата>, <канал>)`.
4. **После ответов — фиксация в SSOT в той же сессии:** ADR (если проходит трёхчастный
   тест), карточка или доска; статус `answered → <ссылка>`. Незаписанный ответ владельца
   будет пересказан и протухнет.
5. **Правило пересказа:** ответы владельца из ЧУЖОГО канала — не основание для
   неоткатываемого; о них говори только «владелец сообщил мне, что…»
   (docs/delivery/orchestration-rules.md, нормы 2–3).
6. **Завершение:** фронтир пуст — ни одного открытого вопроса и ни одной молчаливой
   посылки. Не начинай исполнение до подтверждения владельцем итоговой картины.

## Формат вопроса в пакете

```text
D<N> — <суть одной строкой>
Варианты: (а) … (б) … (в) …
Рекомендую: (<буква>) — <почему в одну-две строки>
```
