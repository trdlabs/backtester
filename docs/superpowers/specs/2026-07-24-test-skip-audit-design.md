# Test-skip audit (TQ-1) — design

Дата: 2026-07-24
Карточка: control-center [`test-quality-hardening`](../../../../control-center/docs/delivery/initiatives/test-quality-hardening.md), пункт TQ-1
Репо: `trading-backtester`

## Проблема

Отчёт 15 (`docs/analysis/15-ci-testing-observability-audit.md`) насчитал «51 файл
со skip в backtester» и потребовал классифицировать их: условные (pg/docker-gated)
против молча выключенных. Само число ничего не доказывает — `grep '.skip'` ловит и
`describe.skipIf(!DOCKER_AVAILABLE)` (честный гейт), и `it.skip(...)` (выключенный
тест). Пока классификации нет, любые пороги coverage (TQ-2) строятся поверх
неизвестной доли мёртвых тестов.

Разовый отчёт проблему не закрывает: через месяц в репо появится новый `it.skip`,
и картина снова разъедется. Нужен машинный классификатор, который живёт в CI.

## Решение

Скрипт-классификатор + гейт в обычном тестовом прогоне.

### 1. `apps/backtester/scripts/audit-test-skips.mts`

Статический сканер тестовых файлов (`**/*.test.ts` в `apps/` и `packages/`, минус
`node_modules`/`dist`). Для каждого сайта модификатора vitest выдаёт запись:
файл, строка, вид (`describe`/`it`/`test`), модификатор, выражение гейта, класс.

Классы:

| Класс | Что это | Примеры |
| --- | --- | --- |
| `gated` | `.skipIf(expr)` / `.runIf(expr)` — исполнение зависит от среды | `!DOCKER_AVAILABLE`, `!PG_AVAILABLE`, `!factory.available` |
| `allowed` | безусловный `.skip`/`.todo` с прагмой-обоснованием | `it.skip` под `// skip-audit:allow — …` |
| `unconditional` | безусловный `.skip`/`.todo` без прагмы | нарушение |
| `focused` | `.only` | нарушение всегда |

`gated` дополнительно разбивается по виду гейта (`docker`, `postgres`,
`store-factory`, `fixture-file`, `env-opt-in`, `other`) — «other» и есть та
самая ad-hoc-поверхность, которую карточка просит свести к единому паттерну.

Разбор — текстовый, со сбалансированным поиском закрывающей скобки для выражения
гейта. TS AST не нужен: сайты модификаторов однострочные по факту репо, а
ложноположительные строки внутри комментариев/строковых литералов отсеиваются
предварительной вырезкой комментариев.

Режимы:

- по умолчанию — markdown-отчёт в stdout (сводная таблица + список нарушений);
- `--json` — машинный вывод для CI/агрегатора;
- `--check` — код возврата 1, если есть `focused` или `unconditional`.

### 2. Прагма-аллоулист

Безусловный skip легален, только если строкой выше стоит

```ts
// skip-audit:allow — <причина>
it.skip('…', …)
```

Обоснование живёт рядом с кодом, а не в отдельном файле, который дрейфует. При
удалении теста прагма уходит вместе с ним.

### 3. Гейт в `pnpm test`

`apps/backtester/test/skip-audit.test.ts`:

1. юнит-тесты классификатора на синтетических исходниках (все четыре класса +
   вложенные скобки в выражении гейта + skip внутри комментария);
2. один интеграционный тест: аудит реального дерева репо не находит ни `focused`,
   ни `unconditional`.

CI-workflow не трогаем — гейт едет внутри обычного `vitest run`.

### 4. Приведение существующей поверхности

Найдено сканированием (2026-07-24): 50 `describe.skipIf` + 4 `it.skipIf`
(все — среда), 1 безусловный `it.skip`, 1 тернарный псевдо-гейт.

- `test/golden-sync.test.ts` — `const crossRepo = platformReachable ? it : it.skip`
  переписывается в канонический `it.skipIf(!platformReachable)`;
- `test/long-oi-parity/signal-parity.test.ts` — задокументированный отложенный
  тест (`DEFERRED: platform ctx.market fix`) получает прагму `skip-audit:allow`.

## Что НЕ делается

- TQ-2 (coverage-инструментация) — отдельный пункт карточки, отдельная волна;
- аудит `trading-lab` — другой репо, другая сессия (карточка TQ-1 покрывает оба,
  но правило «один репо — одна ветка за раз» разводит их);
- переписывание самих условных гейтов: `DOCKER_AVAILABLE`/`PG_AVAILABLE` из
  `test/store-factories.ts` уже и есть единый паттерн, отчёт лишь подтверждает
  это цифрами.

## Критерии готовности

1. `pnpm exec tsx apps/backtester/scripts/audit-test-skips.mts` печатает таблицу
   по всему репо;
2. `--check` возвращает 0 на текущем main после правок из §4;
3. `pnpm test` зелёный, включая новый `skip-audit.test.ts`;
4. отчёт с цифрами внесён в карточку `test-quality-hardening` (rule 8).
